# 小游戏盒子（Games Box）

纯静态的网页小游戏合集：手机浏览器打开就能玩，**断网也能玩**。每个游戏都是一个单文件自包含 HTML，零外部依赖。
另附一个最小 WebView 壳工程，可打成离线 APK 装到安卓设备上当原生 App 用。

## 火箭车：生命值 / 连击护盾 / 大货车

这一版把原来的「3 条命 + 燃油」两套数值**合并成一个生命值**：

- **生命值既是血也是燃料**：随行驶自然消耗，跑得越快掉得越快（停车也慢慢掉）；
  生命归零即结束（撞光 = 撞毁，耗光 = 力竭）。绿星回血，每跑完一段补一次。
- **撞车按车型扣血**：路障 30 < 小车 40 < 卡车 60 < **大货车 80**。大货车最重最慢（橙黑危险条纹 + 「危」字），
  **护盾对它无效**。
- **油箱连击**：吃红/绿星进入喷火后再吃一个 → **阶段 2 护盾**（青色能量罩，撞障碍/小车直接撞飞不扣血，撞完消失）；
  再吃一个 → **阶段 3**（金色护盾，撞飞小车还不掉盾）；之后再吃 → 加速与护盾各延长 1/3 时长。
- **死亡演出**：结束后**不立刻弹窗**——撞毁有子弹时间 + 爆炸 + 残骸翻滚趴窝，力竭/时间到是熄火滑停 + 抛锚双闪，
  0.85 秒后画布浮出大字「撞 毁 了」，演完（撞毁 2.9s / 其余 2.6s）才弹结算；大字出来后可轻点跳过。

### 调参页 `web/racer/editor.html`

不用滑块，全是数字输入框（− / ＋ 步进 + 直接输入），参数存本机 `localStorage`，下次打开游戏自动生效：

- **对象图鉴**：锥桶 / 油桶 / 跑车 / 轿车 / 变道车 / 卡车 / 大货车，每种一张缩略图（照游戏画法重画），
  标注体型与行为，**每种形象的扣血和行驶速度可单独调**（同档形象也能设不同值）。
- **全局参数**：正常上限 / 红星上限 / 红星持续 / 开局时间 / 过关加时 / 生命自然消耗 / 绿星回血 / 每过一段补。
- 底部「换算结果」实时给出各档伤害、「能撞几次」、全速与停车各能撑多久；可一键复制为常数代码。

> 调参键是 `gracer_cfg`。伤害**允许 0**（= 撞了不扣血），所以游戏侧判断用 `>= 0`，不能用「假值跳过」。

## 快速开始

```bash
# 起本地站（推荐：自带 no-store，改完刷新就是新的）
python ops/serve_site.py 4321 web

# 或者
python -m http.server 4321 --directory web --bind 0.0.0.0
```

- 本机：<http://127.0.0.1:4321/>
- 手机：连同一 WiFi 后访问 `http://<本机局域网IP>:4321/`（游戏都是触屏操作，手机体验更完整）
- 自检：`curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:4321/` → 期望 `200`

> 站点根必须是 `web/`（游戏内返回键是绝对路由 `href="/"`）。用 `http.server` 的话改完代码要**强刷**，
> 因为它只发 `Last-Modified`，浏览器会按启发式规则缓存 HTML。

## 测试

每个游戏都有独立的回归测试（`tools/test_<游戏>.js`），用假 DOM + 假 canvas 把游戏脚本跑起来，
断言规则、边界与整局行为。全部用 Node 直接跑，无第三方依赖：

```bash

node tools/test_racer_cfg.js    # 火箭车调参链路：67 项
node tools/test_2048.js         # 92 项
node tools/test_blockpuzzle.js  # 96 项
node tools/test_breakout.js     # 23 项
node tools/test_frog.js         # 53 项
node tools/test_klotski.js      # 190 项
node tools/test_marble.js       # 弹珠乐园逻辑：449 项
node tools/test_marble_ui.js    # 弹珠乐园**真机布局**：61 项（需真 Chrome + 本地站，见下）
node tools/test_othello.js      # 黑白棋整局对局 + 计时断言
node tools/test_parking.js      # 停车场华容道：77 项
node tools/test_sokoban.js      # 两套关卡逐关重放解法：30 项
node tools/test_watersort.js    # 倒水分拣：48 项
```

合计 1100+ 项断言，全绿（2026-10-13 实测）。

### 为什么弹珠乐园有**两个**测试文件

`test_marble.js` 跑在**假 DOM** 里（无浏览器），适合逻辑、物理、规则、边界；
但它测不了**纯布局** —— 假 DOM 里 CSS 完全不生效（`clientWidth/Height` 都是写死值），
「按钮够不够大、会不会换行、会不会溢出」在那里量出来都是假的。

所以补了 `tools/test_marble_ui.js`：起**真无头 Chrome**、按 6 种竖屏手机尺寸
（320×568 → 414×896）真渲染，用 `getBoundingClientRect()` 量真实像素。

```bash
python ops/serve_site.py 4321 web      # 先起站（探测页要与游戏同源）
node tools/test_marble_ui.js           # 再跑
```

- 探测页会临时写进 `web/_ui_probe.html`，**跑完自动删除**（进站点根是为了同源，否则读不了 iframe DOM）。
- 找不到 Chrome / 拿不到 DOM 时脚本**跳过并以 0 退出**，不会在无浏览器环境里永远红。
- ⚠️ 数值断言一律走 `okNum()`：任何 `NaN/null/undefined` 直接判失败。
  起因是「控件条不溢出」那条曾拿 `undefined` 比大小 → `null <= 1` 恒真 → **假绿**
  （打印出来是 `超出 nullpx`）。纯 CSS 的可见 bug 最容易被这类假绿放过去。

### 弹珠乐园：炮口方向键的尺寸（竖屏手机）

用户反馈：◀ ▶ 在竖屏手机上**太小、按着别扭、容易按错**。

量出来的原因是两个叠加：**按钮本身只有 54×58px**（低于 44px 触摸目标的舒适区），
而且 **◀ 与 ▶ 之间只隔 8px** —— 拇指点下去很容易落进中间那道缝里、按成相反方向。

改法（不是简单等比放大，而是**把最容易按错的那一对单独拉开**）：

| | 原来 | 现在（≥360px）| 极窄屏（≤330px）|
|---|---|---|---|
| 方向键 | 54×58 | **76×72** | 64×66 |
| 箭头字号 | 20px | **28px** | 24px |
| ◀↔▶ 间隙 | 8px | **24px** | 10px |
| ◀↔▶ 中心距 | 62px | **100px** | 82px |

- 用 `.ctl .aim + .aim{margin-left}` 只拉开**方向键之间**；它与发射键之间仍用基础 `gap`。
- 发射键文字改 `clamp(12px,3.6vw,15px)` + `min-width:0`，窄屏不换行、不溢出。
- `@media (max-width:330px)` 兜一档，320px 老机型也放得下。
- 实测画布仍占视口 **77%~85%**，没有为了放大按钮把场地挤没。

### 弹珠乐园：墙边撞针要留距（`WALL_PEG_GAP`）

用户反馈：两侧各有几颗钉离墙太近，**弹力不够时小球会被挤在钉与墙之间卡住**。

**几何推导**（这是根因，不是调参问题）：球贴墙时球心 `x = fieldL + RB = 12.5`；
球与钉不重叠要求中心距 ≥ `RB + RP = 11.5`。所以钉心距墙若 **< 2·RB + RP = 18**，
贴墙的球就**必然**与这颗钉重叠 —— 墙把球钳在 12.5、钉又把球往外推，两边在同一帧里互相打架。

- 实测病征：钉距墙 15 时，钉会把球**顶到墙内界之外**（球心被推到 x=9.50 < 合法下限 12.50）。
- 取值扫了 12/18/20/22/24/26/30（每次 200 局 × 12 发真实物理）：
  `12 → 104/2223（4.7%）`、`18 → 31/2236`、**`20 → 0/2225`**、22 及以上都是 0。
- 所以取**刚好够用的 20**（不往上加）：钉数只从 70 掉到 67，钉档占比分布与原来基本一致
  （rMax p95 `53.8%` vs 旧 `53.7%`）—— 手感改动最小。

回归测试锁了两层：静态（60 局里没有钉落在 `2·RB+RP` 危险区内）+
动态（40 局 × 12 发，检查「贴墙且紧贴钉」与「球心被顶穿墙」两种病征各 0 发），
并附带一条**反证**（把钉强行摆到距墙 15，确认病征复现）—— 否则「0 发」可能只是采样不足。
### 弹珠乐园：撞针弹力与调参实验

撞针分 4 档（`PEG_KINDS`）：软 0.46（灰白）/ 普 0.74（粉）/ 弹 0.94（绿）/ 超弹 1.06（金，>1 会加能量把球顶回上方）。
每局由 `rollPegMix()` 随机抽权重（带主基调 + 上限封顶），再按纵深偏置落到钉阵上。

`tools/bench_marble_pegs.js` 是用来调这套参数的实验台（每档几百发真实物理）：

```bash
node tools/bench_marble_pegs.js 600                                  # 内置对照表
node tools/bench_marble_pegs.js 600 "旧版|0,1,0,0|0" "随机|-|-"       # mix 写 - = 用游戏自己 roll 的
```

实测（600 发/档，无道具、炮口 0°）：球待在「上半场」的绝对时长 **1.98s → 2.39s（+21%）**，
弹回上方次数 1.32 → 1.56，撞钉数 30 → 46；代价是 0.7% 的球会打到 14s 兜底。

### 弹珠乐园：撞针状态的寿命（`PEG_LIFE`）

地雷 / 火力球炸掉的钉、冰封球冻住的钉，**不再「回合结束就复原」**，而是保持 `PEG_LIFE=3` 回合：
每回合结束 `life - 1`，掉到 0 才长回来（跟道具那套 `ITEM_LIFE` 同一节奏）。最后一回合外圈闪红提醒。

- 两种状态互斥、**共用一份 `life`**：冻住的钉被撞碎 = 一次新的状态变化，寿命重新起算。
- 已经碎掉的钉不会被重复炸到（`explode` 跳过），所以寿命不会靠反复炸来「续」。
- 碎掉的钉在画面上留一个暗色凹痕（看得出「这里本来有颗钉」），冻结的是冰蓝棱角。
- `tools/bench_marble_peg_life.js` 用来验证「钉场会不会被炸空」：

```bash
node tools/bench_marble_peg_life.js 12 0.55     # 12 局，每回合 55% 概率吃到改变钉状态的道具
```

实测：全程最低完整度 **72.6%**、平均末回合 92.5% —— 3 回合复原够快，钉场不会被炸空。

### 弹珠乐园：地雷的外观（黑炸弹 + 白骷髅）

地雷跟其它道具不一样，它**几乎只有负面效果**（吃到 = 这颗白打 + 周围一大片钉全炸没），
混在「彩色圆牌」里玩家会误吃 —— 所以给它单独一套外观（`ITEMS.MINE.shape = 'bomb'`）：

- **黑色炸弹球体**（径向渐变留立体感）+ **纯矢量白骷髅**（眼窝/鼻腔/牙缝挖空），
  不用 emoji、不依赖字体，缺字体的环境也画得出来。
- **红色脉冲光环** + 引线火花 —— 其它道具是白色柔光，一眼就能区分。
- **虚线爆炸预警圈**：按真实爆炸半径 `MINE_R=48` 画出来。地雷真正可怕的是「吃到后炸一大片」，
  光看一个小圆牌完全想不到，所以把范围直接标出来。
- 画得比判定略大（画 `ITEM_R+1.2`、判定仍是 `ITEM_R`）：视觉预警偏大是安全方向 ——
  宁可多躲，不会「看着没碰到却炸了」。
- 寿命点、最后一回合闪烁/红圈跟其它道具**共用同一套**提醒机制。
  ⚠️ 坑：`drawMine` 内部为画脉冲光环会临时调低 `globalAlpha`，**必须还原成进来时的值而不是写死 1**，
  否则地雷在最后一回合反而不闪（已加回归测试锁住）。

### 弹珠乐园：入口桶变化的寿命（`ENTRANCE_LIFE`）

`Left` / `Right` 倍率、`错位`、`石化封桶` 这三类「入口桶变化」**也不再「回合结束就复原」**，
保持 `ENTRANCE_LIFE=3` 回合，跟道具 / 撞针同一套节奏。四种变化**共用一份 `life`**
（它们本来就都作用在「入口数字」这一个东西上，`effNums()` 把倍率 + 错位 + 石化一起算成最终数字）。
再吃到任意一种 = 一次新的状态变化 → 寿命重新起算。

- HUD 徽章带「还剩几回合」后缀（`左+2·3`），最后一回合变红；
  桶排进入最后一回合时整排描一圈红色脉冲边，提醒「下回合就恢复底表了」。
- **⚠️ 两个必须做的配套约束**（不然这个改动会把游戏搞死，都是实测发现的）：

  1. **`Left` / `Right` 互斥**：`effNums()` 里「L 让右侧变负、R 让左侧变负」，
     两者同时在场 → 9 个桶**全是负数**（只剩 0 桶）。以前效果只活一回合，最多挨一回合；
     现在要保持 3 回合 → 先吃 L 再吃 R 就会连挨 3 回合全负、几乎没法得分。
     所以改成**吃到相反方向 = 抵消对方一层**（同向仍是叠加加倍）。
  2. **`SEAL_MAX=3`**：石化以前一回合最多封 2 个、回合末就复原；现在保持 3 回合会**累积**
     （2+2+2 = 6/9 个桶被封），球到处被弹回来。所以给同时被封的入口数封顶 3 个。

- `tools/bench_marble_entrance.js` 用来验证改动前后的经济性（会瞄准的玩家模型）：

```bash
node tools/bench_marble_entrance.js 12 0.35          # 12 局，每回合 35% 概率吃到入口变化道具
node tools/bench_marble_entrance.js 12 0.35 random   # 第 4 个参数 random = 随机瞄准（对照）
```

实测（12 局 / 35%，打最值钱的桶）：平均每回合加球 **1.66**，旧行为（回合末即复原）**1.67** ——
差 **-0.4%**，经济性基本不变，但「吃到的东西留得住」了。峰值封桶 3/9，始终留着 6 个可得分入口。

> ⚠️ 教训：`bench` 的瞄准模型会显著影响结论。一开始用「随机瞄准」测，得出「新行为比旧行为差 290%」的
> 吓人结论 —— 其实是把 `L/R` 的设计意图（左边加倍、右边变负，**本来就该往左边打**）当成了随机挨罚。
> 换成「打最值钱的桶」后差距就消失了。

### 弹珠乐园：首屏玩法提示（可关闭）

用户反馈过两个问题，都已修：

1. **位置太靠下**：原来 `cy = (fieldT+mouthY)*0.44` 只是个凭感觉的系数，实际上会让面板底边
   （**507**）压过桶口（`mouthY=498`）。现在改成**按面板真实高度在场地里居中**：
   面板变成 `132..454`、中心 293 对齐场地中心 299，完整落在场地内。
   矩形计算抽成 `hintRect()`，**绘制与命中检测共用同一份**（避免「画在一处、点判在另一处」）。
2. **没有关闭按钮、不能触屏关闭**：以前只能靠「按发射键/方向键」顺带关掉，
   想先看清规则就得先开一枪。现在三种方式都能关：
   - 右上角 **✕ 按钮**（看得见的关闭入口）
   - **轻点画面任意处**（触屏；命中判定刻意宽松，`hintOn` 期间画布上任意轻点都关）
   - **Esc 键**（键盘）

   关闭逻辑统一走 `closeHint()`（幂等，返回是否真的关了）。
   ⚠️ 画布的 `pointerdown` **只在 `hintOn` 时消费事件**，平时绝不拦截 ——
   画布本身不参与蓄力（控制已分离到 ◀▶ 与发射键），所以不会和游戏操作打架。

### 弹珠乐园：会挪窝的金冠（`crownI`）

**金冠恒有且仅有 1 个；每个回合（每次发球）开始时重掷位置：30% 换到别的筒，其余 70% 回 8 号筒。
落进金冠筒 = 正常得分 + 额外 1up（加一条命）。**

- `WIN_I` 与 `crownI` 是**两个不同的东西**，以前是同一个常量：
  - `WIN_I = 4` 是**几何中心**（9 格的中间那格），`effNums()` 的 L/R 分界、`makePerm()` 的
    「中间不动」都靠它 —— **必须永远固定**，不能跟着金冠跑。
  - `crownI` 才是金冠所在筒（默认 `CROWN_DEF_I = 4`）。
- **重掷时机在 `newRound()` 里**，所以「换新局」和「每次回合结束」都会掷一次 ——
  也就是玩家每次能发球之前，金冠位置都刚掷过。
- 换筒时从「**除默认筒以外**」的 8 个筒里等概率挑一个 —— 不会出现「换到原地」白白消耗掉那 30%。
  实测 5000 次重掷换筒率 **30.2%**、逐回合看 **29.5%**，8 个别的筒都出现过且分布均匀。
- 金冠**可以落在底表为 0 的筒上**（1 号 / 7 号），那时它就是「一条命的筒」。
  ⚠️ 画金冠的守卫**不能写 `n !== 0`**（原来固定在第 4 格、8 分，所以有这条件）——
  否则金冠跑到 0 分筒上就看不见了。
- 落进金冠筒的 1up 是**立即到账**（不是回合末），这样「最后一发靠金冠续命」的手感才成立。
- ⚠️ 必须排除**被封住**的桶：水泥筒会把球弹回去，物理上根本进不去，
  但超时兜底仍可能走到 `landBucket`，那种情况不该给命（**这个 bug 是测试抓出来的**）。
- ⚠️ **只在位置真的变了时才 toast**：每回合都弹会一直盖住画面，而 70% 的情况是原地不动。

#### ⚠️ 测试要用 `__marblePinCrown` 而不是一次性设置

金冠现在**每回合重掷**，所以「设一次就完事」的写法会被下一回合覆盖掉。测试里要锁位置必须用
`__marblePinCrown(i)`（它**同时**设置 `crownPin` 和当前回合的 `crownI`）；
`__marblePinCrown(-1)` 解锁。`reset()` 会清掉 pin（换新局就该正常重掷）。

> 踩过的坑：第一版 pin 只设 `crownPin` 没设 `crownI` → 当前回合不生效，测试全线失败。

#### ⚠️ 另一个真 bug：玩家「玩了好久都没见过金冠挪窝」

**根因不在金冠逻辑，在启动代码**：原来写的是 `reset(1)`（固定种子「首局可预期」），
于是**每次刷新页面/首次打开看到的都是同一局** —— 同一个钉阵、金冠永远在 8 号筒。
只在手机上用「刷新」而很少点「再来一次」的玩家，就永远看不到挪窝。

已改成启动也用**随机种子**（与「再来一次」一致）；需要复现某一局时用
`__marbleReset(seed)` 或 URL 上的 `?seed=`。实测连续「刷新」8 次：**8/8 个不同种子**。


### 弹珠乐园：生命与分数分离（`START_LIVES`）

**这是核心数值模型的一次重构**：以前「弹珠数」既是命也是分（落桶加球 = 加命），现在拆成两套独立数值：

| | 来源 | 消耗 | 说明 |
|---|---|---|---|
| **生命** `lives` | 开局 `START_LIVES=10`；只有 `1up/2up/3up` 能补 | **发射扣 1** | 归 0 即结束 |
| **分数** `score` | **只有落桶得分**（桶上是几就得「几 × `SCORE_MULT`」分；被 `L/R` 改成负数就扣分） | 不消耗 | 最高分落盘 `marble_best_score` |

- 落桶**不再补命** → 「打得好」体现在分数上，而不是「能多打几发」。
- 分数**可以为负**（`R` 道具把左侧打成负数时），与生命互不影响。
- HUD 左=生命（红心）/ 右=分数，最高分以小字放在分数胶囊下方。
  ⚠️ ×100 之后位数变多，HUD 的分数/最高分**字号按位数收**（否则 6 位以上会顶出胶囊）。
- ⚠️ 落盘键从 `marble_best` 换成了 `marble_best_score`（语义从「最高弹珠数」变成「最高分」）。

#### 分数倍率 `SCORE_MULT = 100`

用户要求「得到的分数 ×100」—— 个位数/十位数的分数看着不好看（8 分、16 分太寒酸）。

⚠️ 关键实现选择：倍率加在**计分那一刻**（`landBucket` 里的 `roundGain += n * SCORE_MULT`），
**不是只改显示**。这样 `score` / `best` / `localStorage` / 结算面板 / 本回合累计
全都是同一套数值，不会出现「界面显示 ×100、实际存的却是原始值」那种两套账。

`landBucket` 内部把两个概念分得很清楚（测试也守着这条）：

- `n` = **桶上的原始数字**（绘制桶面、音高、返回给测试都用它，**不乘倍率**）
- `gained = n * SCORE_MULT` = **实际得分**（进 `roundGain` / 飘字）


### 弹珠乐园：爆炸炸道具 + 连环爆炸

- 爆炸会**炸掉范围内的道具**（`(r + ITEM_R)` 判定）。
- 炸到的道具若是**地雷 → 连环爆炸**：以该地雷为中心再炸一次（半径 `MINE_R`），可以一层层扩散。
- ⚠️ 连锁是**同步递归**完成的，**不是 `setTimeout`**：本作的物理/结算全靠手工步进驱动，
  延迟爆炸会脱离这一帧的状态（可能拖到回合结束之后才炸），而且测试没法确定性断言。
  所以伤害立即结算，只把**音效**按 `depth` 错开一点点，听感上仍有「一个接一个」的层次。
- 收集「要连锁的地雷」时要**先收集再递归**（不能在遍历 `items` 的中途递归），
  且用倒序遍历配 `splice`；`CHAIN_MAX=12` 兜底防无限递归。
- 实测：4 颗间距 40 的地雷 + 3 个普通道具，引爆第 1 颗 → `chained=4`、`killedItems=7`、场上清空。

### 弹珠乐园：入口边缘闪烁 · 分裂一变四 · UP 字形

- **入口外边缘闪烁**：只要入口被 `L` / `R` / `错位` / `封桶` 改过，入口区外边缘就画成会呼吸的亮边，
  提醒「现在的入口不是底表」。颜色按生效的变化走（倍率=金 / 错位=紫 / 封桶=灰白，多种叠加取优先级最高），
  最后一回合统一变红、加快节奏并加粗。
  ⚠️ 只画一条细线在花花绿绿的桶排上**太容易被忽略**，所以加了 `shadowBlur` 光晕才够醒目（实测调过）。
- **分裂一变四**（`SPLIT_N=4`）：原来是「一变三」，现在每次多裂出一个小球。
  四个方向仍铺在**原来的张角**（±0.55 rad）内均匀分开，所以「散得多开」的观感不变，只是从 3 条变 4 条。
- **UP 字形**：道具牌面写 `1up` / `2up` / `3up`（原来是 `+1` / `+2` / `+3`）。
  3 个字比 1 个字宽，所以字号按字数收（`ITEM_FONT = {1:11.5, 2:9, 3:7.4}`），保证塞得进 19px 的圆牌。

> 测试脚本直接读 `web/**/index.html` 里的内联 `<script>`，所以**改完游戏不用额外构建**，跑测试即可。

### ⚠️ 一个重要发现：`.sok` 文件附带的解并不是最优解

经典集原来的「参考最优」取自关卡文件里附带的解。用可采纳 A* 重算后发现**那些解普遍不是最优**：

| 关卡 | `.sok` 声明 | 真最优 |
|---|---|---|
| 经典集第 1 关 | 14 推 | **12 推** |
| 经典集第 8 关 | 19 推 | **15 推** |
| 经典集第 18 关 | 40 推 | **14 推** |

（用独立的 Python 裸规则重放器逐个复核过，新解全部合法。）所以游戏里现在按 `best.opt` 区分标注：
`true` 显示「（推动数最优）」，`false` 显示「（参考解，未证最优）」。

**`best.pushes` 的可信来源是 `tools/solver3.js`**：h 用「盒子→目标最小代价完美匹配」（各目标 BFS 距离
+ 匈牙利算法）作可采纳启发式，且剪枝只用「死格」与「2x2 冻结块」两种充分条件，
所以 weight=1 时给出的是**推动数最优**；另外终止条件必须是「目标态被弹出」而不是「刚生成就返回」，
否则可能提前收工拿到次优解。

## APK 构建（离线安装包）

```bash
bash android/build_apk.sh              # 构建 + 签名 + 校验 + 同步 releases/
bash android/build_apk.sh --genkey     # 密钥丢失时先生成一把新的
```

- 工具链路径用环境变量 `ANDROID_BASE` 指定（默认 `/opt/data/android-build/tools`：
  JDK 17 + build-tools 35.0.0 + android-35 平台）。**不需要 Android Studio、gradle 或 sudo**。
- 签名口令来自环境变量 `GAMEBOX_KS_PASS` / `GAMEBOX_KEY_PASS`，否则读 `private/keystore.pass`。
  这两个文件都在 `private/`（已 gitignore）。
- 脚本流程：`aapt2 compile` → `aapt2 link` → `javac` → `d8` → 把 `classes.dex` 装回 APK →
  `zipalign -P 16 4` → `apksigner sign` → `apksigner verify` / `zipalign -c` / `aapt2 dump badging`。
- 产物：`android/output/小游戏盒子离线版.apk`，并同步到 `releases/`（版本化副本 + 最新副本）。

### 已知坑（脚本里已规避）

| 现象 | 原因 / 处理 |
|---|---|
| `aapt2 compile --dir` 报 `Is a directory` | 逐文件 `compile`，不要传 `--dir` 指向已有输出目录 |
| `d8` 报 `Unsupported source file type` | 不能传 class **目录**，用 argfile 传显式 `.class` 列表 |
| `aapt2 link` 资源覆盖报错 | 加 `--auto-add-overlay` |
| `onConsoleMessage` 编译不过 | API 35 要求返回 `boolean`，不是 `void` |
| 断网装好后白屏 | assets 里必须是相对链接（`othello/index.html`、`../index.html`），不能写站点根 `/othello/` |
| 网页有、APK 没有 | 加新游戏后忘了跑 `sync_assets.py` |

> 静态校验通过 ≠ 真机验收。最终仍需在设备上**飞行模式**启动，验证主页、各游戏、触控、音效与进度保存。

## 加新游戏时要动的地方

1. 新建 `web/<游戏名>/index.html`（单文件自包含、零外部依赖，返回键写 `href="/"`）。
2. 在 `web/index.html` 的卡片列表里加一张卡（`href="/<游戏名>/"`）。
3. 跑 `python android/sync_assets.py` 同步离线资源 —— **网页版和 APK 版的链接写法不同**
   （网页版 `/othello/`，离线版 `othello/index.html`），这一步不跑，新游戏就会「网页上有、APK 里没有」。
   `build_apk.sh` 已内置这一步，打 APK 时会自动同步。
4. 顺手补一个 `tools/test_<游戏名>.js`（照现有测试抄骨架：假 DOM + 假 canvas + 断言）。

## Git 工作流

- `master` 是主干；**一个功能/一个游戏一条 `feat/*` 分支**，做完合回 `master`。
- 远程：`git@github.com:ashlam/game-box.git`（origin）。

```bash
git switch -c feat/xxx
# ... 改完跑测试 ...
node tools/test_xxx.js
python android/sync_assets.py        # 动了 web/ 就同步离线资源
git add -A && git commit -m "feat(xxx): ..."
git switch master && git merge --no-ff feat/xxx
git push origin master
```

## 常驻守护（服务挂了自动拉起）

`ops/games_guard.py` 被 cron 每 5 分钟调用一次：服务正常 → **零输出静默**；服务掉线 → 自动拉起并留一条记录；
站点目录丢失 → 告警。手动验证：直接跑脚本应**无输出**；`kill` 掉服务再跑，应恢复 200。

> 历史上它部署在 NAS 的 Hermes cronjob（`no_agent` 模式）下，路径与 IP 都写死在旧环境里；
> 现在脚本本身不依赖那些路径，换环境只要保证「能读到 `web/` 并起在 4321」即可。
